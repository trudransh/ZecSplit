# Key decisions

The design choices behind ZecSplit and why we made them.

| Decision                                                                                                           | Why                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ZEC → BTC first** (the exit)                                                                                     | It is the direction shielded holders lack a private route for. The user pays from the Zcash wallet they already have.                                                                       |
| **Shared key on Zcash, all logic on Bitcoin** (Gugger's construction)                                              | An adaptor signature on the Zcash side is open to front-running. Keeping the ZEC under `σ·(s_a + s_b)` needs no Zcash scripting and no consensus change.                                    |
| **P2WSH 2-of-2 with ECDSA adaptor signatures** (`ecdsa_fun`)                                                       | Mature, well-understood Bitcoin primitives. Taproot with Schnorr adaptors is a later privacy upgrade.                                                                                       |
| **Cross-curve DLEq from Serai's `dleq`, vendored unmodified**, plus explicit proofs of knowledge and commit-reveal | Reuses a reviewed implementation instead of hand-rolling cryptography. Commit-reveal and proofs of knowledge close rogue-key attacks independently of the DLEq.                             |
| **Shares are integers in `[1, 2^254)`**                                                                            | Valid scalars on both Pallas and secp256k1 without reduction. A check stricter than what the DLEq guarantees would itself be a stuck-funds attack.                                          |
| **Viewing keys `nk`, `rivk` derived from the transcript**                                                          | Neither party can choose them, and both compute them identically.                                                                                                                           |
| **Web UI plus a local engine; no keys in the browser**                                                             | Swaps last hours, hold secrets and have deadlines. A browser tab can't be trusted with that.                                                                                                |
| **The user pays ZEC with a ZIP 321 request from any wallet**                                                       | No Zcash wallet inside ZecSplit on the happy path, and no transparent source.                                                                                                               |
| **Maker checks Zcash on its own Zebra; taker checks Bitcoin on two sources**                                       | Each party trusts only data it can't be lied to about.                                                                                                                                      |
| **Pre-release librustzcash crates; branch ID read from the node**                                                  | Ironwood and NU7 need them, and signing stays valid across the upgrade.                                                                                                                     |
| **Pure, write-ahead state machines**                                                                               | Every transition is saved before its side effect, so a crash at any point resumes safely.                                                                                                   |
| **Sessions saved as inputs and rebuilt by replay**                                                                 | A restored session re-runs every check and, with deterministic signing, produces byte-identical messages and transactions. The same sealed bundle is the recovery file (`age` with scrypt). |
| **Idempotent setup messages**                                                                                      | After a restart either side can re-send; identical repeats are answered, conflicting ones refused. A second lock template can't replace one already signed.                                 |
| **No mainnet**                                                                                                     | Unaudited code. Regtest for development and CI, Zcash testnet plus Bitcoin signet for the live demo.                                                                                        |
