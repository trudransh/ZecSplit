# Notation and quote

Roles, groups, keys, hashes, and the signed quote (spec §1, §2).

## Roles

| Symbol        | Role                                              |
| ------------- | ------------------------------------------------- |
| **Alice (A)** | Holds ZEC, wants BTC. In v1 she is the **taker**. |
| **Bob (B)**   | Holds BTC, wants ZEC. In v1 he is the **maker**.  |

## Groups

| Symbol | Meaning                                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `G_P`  | Pallas, with base point `SpendAuthG`, the Orchard spend-authorization generator (`ak = [ask]·SpendAuthG`). Scalar field `F_q`, order ≈ 2²⁵⁴. |
| `G_S`  | secp256k1, with the standard generator `G`. Order `n` ≈ 2²⁵⁶.                                                                                |

## Keys

* **Secret shares** `s_a`, `s_b`: integers in `[1, 2^254)`, valid as scalars in both groups (2²⁵⁴ is below both group orders). Each is generated by the cross-group DLEq prover, never reduced independently.
* **Public shares**: `S_a^P = [s_a]·SpendAuthG` and `S_a^S = [s_a]·G`, and the same for `b`. `S_x^S` is also party x's **adaptor point** on Bitcoin, written `Y_x`.
* **Bitcoin multisig keys** `k_a`, `k_b`: secp256k1 private keys, independent of the shares. `K_a`, `K_b` are their compressed public keys.

## Hashes and encoding

* `H256(tag, m)` is BLAKE2b-256 with a 16-byte personalization `tag`; `H512` is BLAKE2b-512 with the same.
* Tags are ASCII, NUL-padded to 16 bytes: `HK_commit_v1`, `HK_transcript_v1`, `HK_nk_v1`, `HK_rivk_v1`, `HK_pok_v1`, `HK_quote_v1`, `HK_dleq_v1`.
* Integers are little-endian unless Bitcoin requires otherwise. Pallas points use the 32-byte compressed encoding; secp256k1 points use SEC1 33-byte compressed.

## The quote (§2)

**§2-R1.** Bob publishes a long-term **maker identity key** (BIP340 Schnorr). The engine pins it in its configuration.

**§2-R2.** The quote is signed by the maker identity key over `H256(HK_quote_v1, canonical_json(quote))`. Alice MUST verify the signature and that the quote hasn't expired before going on.

| Field                      | Type         | Meaning                                                         |
| -------------------------- | ------------ | --------------------------------------------------------------- |
| `protocol_version`         | u16          | `1`                                                             |
| `swap_id`                  | 32 bytes     | Random, chosen by Bob                                           |
| `network`                  | enum         | `regtest`, `test` (Zcash testnet + Bitcoin signet), `main_beta` |
| `zec_amount`               | u64 zatoshis | ZEC Alice pays into the lock                                    |
| `btc_amount`               | u64 sats     | BTC Alice receives                                              |
| `btc_fee_rate`             | u64 sat/vB   | Fixed for all pre-signed transactions                           |
| `t1`                       | u16 blocks   | Relative timelock: lock confirmed → cancel valid                |
| `t2`                       | u16 blocks   | Relative timelock: cancel confirmed → punish valid              |
| `n_conf_btc`, `n_conf_zec` | u16          | Confirmations required                                          |
| `redeem_margin`            | u16 blocks   | Safety margin before `t1` (see the happy path)                  |
| `expires_at`               | unix seconds | Quote expiry (about 60 s)                                       |
